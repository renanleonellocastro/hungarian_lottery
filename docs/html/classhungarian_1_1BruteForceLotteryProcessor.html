Detailed Description

Brute-force lottery processor implementation.

This processor directly compares each player's number against the lottery pick to count matches.

This is probably one of the slowest implementations, but it is straightforward and does not require too much memory. Also this is good to validate other more complex implementations.

Processed container produced by preComputeWinners.

This will be populated inside preComputeWinners so that computeWinners() can read from it. For the brute-force processor, this is simply a vector of players; for other processors it may be an index or cache structure.
